# ZYM 与 Python 性能对比报告

## 1. 测试目的

使用ZYM和Python实现相同的埃拉托斯特尼质数筛算法，在相同计算机、相同输入和相同进程启动方式下比较端到端运行时间，并分析解释型ZYM与Python之间的性能差异。

## 2. 测试程序

- ZYM实现：`benchmark/prime_sieve.zym`
- Python实现：`benchmark/prime_sieve.py`
- 自动测试器：`benchmark/run_comparison.py`
- 原始数据：`benchmark/results/runtime_comparison.csv`
- 优化前数据：`benchmark/results/runtime_comparison_before_optimization.csv`
- 汇总日志：`benchmark/results/runtime_comparison.log`

两份程序均读取一个整数上限，使用布尔数组筛除合数，并输出：

1. 不大于上限的质数数量；
2. 所有这些质数的总和。

自动测试器在计时前比较两份程序的完整stdout。只有结果完全一致时才继续性能测试。

## 3. 测试环境

- 初始测试日期：2026-11-15
- 优化复测日期：2026-11-16
- 操作系统：Windows 11 10.0.26200
- Python：3.12.4
- ZYM：0.1.0
- Git基线：`73acbdef5450d8cca82b1c86769afdcfa44a585e`
- Git状态：dirty，因为性能脚本和报告当时处于提交前审核阶段
- 计时函数：`time.perf_counter()`
- 计时范围：从创建子进程到进程结束的端到端墙钟时间

## 4. 测试方法

- 输入规模：5000、20000、50000；
- 每种规模、每种实现预热1次；
- 每种规模正式运行7轮；
- 奇数轮先运行Python，偶数轮先运行ZYM，降低固定运行顺序产生的偏差；
- 使用7轮耗时的中位数作为结果；
- 每次运行均检查退出码为0且stderr为空；
- 原始42条计时数据全部保存为CSV。

运行命令：

```powershell
python benchmark/run_comparison.py --sizes 5000 20000 50000 --repeats 7 --warmups 1
```

## 5. 正确性验证

| 上限 | 质数数量 | 质数总和 | ZYM/Python输出 |
| ---: | ---: | ---: | --- |
| 5000 | 669 | 1548136 | 完全一致 |
| 20000 | 2262 | 21171191 | 完全一致 |
| 50000 | 5133 | 121013308 | 完全一致 |

## 6. 性能结果

| 输入上限 | ZYM中位耗时 | Python中位耗时 | ZYM/Python耗时比 |
| ---: | ---: | ---: | ---: |
| 5000 | 0.180490秒 | 0.050685秒 | 3.56倍 |
| 20000 | 0.344467秒 | 0.053278秒 | 6.47倍 |
| 50000 | 0.664567秒 | 0.060095秒 | 11.06倍 |

## 7. 结果分析

ZYM在三种规模下均慢于Python，且输入增大后差距扩大。主要原因如下：

1. ZYM是使用Python实现的树遍历解释器。循环中的每次变量读取、数组访问、算术运算和赋值都需要访问AST节点并执行Python层的类型分派。
2. Python脚本由成熟的CPython字节码虚拟机执行，循环和列表操作经过长期优化；ZYM尚未生成字节码，也没有即时编译。
3. 两种实现都包含Python进程启动时间。小规模下约0.05秒的启动成本占比较高，因此5000规模的差距为3.56倍；规模增大后算法执行占比提高，解释器开销更明显。
4. ZYM实现的数组通过运行时类型检查和边界检查访问，这些检查保证了稳定错误信息，但也增加了耗时。

该结果属于课程解释器的合理范围。ZYM的目标是完整、可读、可测试地展示语言实现过程，而不是超过成熟Python运行时的性能。

## 8. 已完成的性能优化

开发阶段已经使用独立的Lexer+Parser基准验证过一项优化：把扫描过程中重复创建的单字符Token映射和字符串转义映射移到模块级常量。优化后前端中位解析耗时由1.213873毫秒降至1.020273毫秒，降低15.95%；吞吐量提高18.98%。详细记录位于 `docs/FRONTEND_PERFORMANCE_LOG.md`。

质数筛初测后又针对执行器做了函数级性能分析。优化内容包括：

1. 不含声明的循环和分支代码块复用当前环境，避免每轮分配作用域对象；
2. 变量查找和赋值由递归调用改为迭代遍历环境链；
3. AST节点分派使用精确类型比较，减少重复的 `isinstance` 调用；
4. 数值二元运算移除重复枚举集合哈希；
5. 原生函数调用直接读取参数数目并调用实现函数，减少包装层调用。

| 输入上限 | 优化前ZYM | 优化后ZYM | 耗时降低 |
| ---: | ---: | ---: | ---: |
| 5000 | 0.208071秒 | 0.180490秒 | 13.26% |
| 20000 | 0.447927秒 | 0.344467秒 | 23.10% |
| 50000 | 0.952376秒 | 0.664567秒 | 30.22% |

在50000规模下，性能分析记录的函数调用数由约1322万次降至约506万次。下一层级的优化方向是把AST编译为ZYM字节码，并在虚拟机中执行紧凑指令。这会改变解释器架构，适合作为后续版本工作。

## 9. 测试限制

- 结果来自一台Windows计算机，可能受到CPU调频和后台程序影响；
- 只测试了质数筛一种算法，不能代表所有程序；
- 测量包含进程启动、读取源码、词法分析、语法分析和执行时间；
- Python和ZYM虽然采用相同算法，但底层列表操作和执行模型不同。

通过预热、多轮测试、交替运行顺序、中位数统计和保存原始CSV，已经尽量降低这些限制对结论的影响。
